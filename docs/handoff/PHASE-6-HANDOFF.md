### 0.3 The three ideas worth carrying forward

1. **A status colour is unobtainable without its glyph and its label.** `StatusViewModel` requires
   all three, so a colour-only badge is not a discouraged option — it cannot be constructed. That is
   REQ-UX-002 enforced by the type system rather than by review.
2. **Published numbers are recomputed, never transcribed.** Every contrast ratio in the brand
   document is recalculated from the palette by test. This caught four wrong figures in a draft of
   §10 — figures that were quotable, plausible, and would have survived any amount of proofreading.
3. **The token indirection pays for itself at exactly one place: the dark sidebar.** A `HealthBadge`
   dropped into the rail resolves `light-green` instead of `green` without knowing a theme exists —
   which is §2.1 rule 3 honoured automatically, and precisely the rule a component author forgets.

### 0.4 Read this before Phase 7 (design-system constraints)

- **Interaction has nowhere to go (DR-041).** The components are built to receive interaction as
  view-model changes — sort state is a column field, filter selection is a filter field, scope is a
  selector field. Nothing dispatches those changes: there is no client runtime and no transport
  (DR-029). Phase 7 must either scope around this or resolve it, and resolving it touches ADR-0006.
- **The UI decides nothing about access.** `requiresCapability` on a navigation destination is a
  *presentation hint* that dims an unusable link. `SECURITY_MODEL.md` §12.1 is binding: the server
  authorises every request from scratch, and a hidden control is never a control.
- **Charts take `PlottableValue`,** which carries both a `display` string and a raw `value`. Render
  `display`. `value` exists for one purpose — mapping onto an axis — and G-FLOAT guards the rest.
- **Every chart view model requires a `textAlternative` and a `dataTable`.** They are not optional
  fields; a chart that cannot be described cannot be constructed.
- **Nothing is browser-verified (DR-042).** Do not describe this UI as WCAG AA conformant. It is
  built to the standard and asserted as far as static rendering allows.

### 0.5 What the gates caught

1. **G-BROWSER's first draft produced seven false positives.** It matched the bare identifier
   `window`, which is a domain term here — a rate-limit window, a trajectory window. Narrowed to
   browser *members*. A gate that cries wolf gets suppressed, and a suppressed gate is not a gate.
2. **G-FLOAT rejected the contrast utility's own `parseInt`.** Converting hex digits looks like an
   obviously-fine coercion, which is what every exemption looks like from inside. It became a table
   lookup.
3. **The brand document's §2 instruction found four wrong numbers.** §2 told Phase 6 to encode the
   ratios as checks rather than prose. Doing so revealed that a draft of §10 published four ratios
   for the functional amber and red that were wrong by up to 0.7. All still clear AA; all corrected.
4. **G-COLOUR forced the shadow into the palette.** `rgba(...)` in the stylesheet is a colour
   literal, so shadow ink is defined once, beside the colour it is derived from.

### 0.6 What was deliberately not done

1. **No executive surface.** Phase 6 builds parts, not screens. Phases 7–11 assemble them.
2. **No charting library, no component library, no client router or state library** — ADR-0017 D-1.
   Each would bring a palette and a type scale that compete with `BRAND_DESIGN_SYSTEM.md`.
3. **No client-side interactivity.** The gallery is static HTML; the evidence drawer is
   `<details>`/`<summary>`. This is a consequence of having no transport, and it has an accessibility
   dividend: the drawer works with no JavaScript at all.
4. **No logo asset and no embedded font.** §1 and §4 forbid both. The identity is set type —
   "GlobalLogic" over "Delivery Intelligence" — with a short orange rule. If a licensed asset arrives
   it drops into `BrandMark` and nothing else moves.
5. **No browser-based accessibility tooling** (DR-042).

## 2. What Phase 7 must NOT assume

1. **That authentication is real.** It is a persona selector guarded by an environment allow-list.
2. **That audit survives a restart.** In memory (DR-024).
3. **That any security header is applied.** Declared and tested; nothing serves them (DR-029).
4. **That an override expires.** Accepted, neither persisted nor enforced (DR-036).
5. **That hiding a control is a control.** It never is, and the payload is already shaped.
6. **That thresholds are approved.** Every band edge and weight remains a synthetic calibration
   candidate.
7. **That `HEALTH-v2` is the health model.** It is `Draft` under C-7.
8. **That the ranking's inputs are settled.** `MET-PORT-007` now returns a ranking (MC-5 resolved),
   but tiers 1 and 2 read `MET-HLTH-011`, whose health model is still open under **C-7**. The
   *ordering* is decided; which band feeds it is not.
9. **That a role name tells it anything.** Personas and roles are decoupled (`SECURITY_MODEL.md`
   §4.1a). Ask for capabilities; never infer them.
10. **That the UI can respond to a click.** `ApplicationGateway` gives Phase 7 a way to *express*
    a query; there is still no client runtime to dispatch one (**DR-044**).
11. **That Green-at-Risk means one thing.** It means two, and they are different metrics
    (`MET-FCST-025`, `MET-HLTH-033`). A screen that shows one label for both has lost the signal.

## 2a. Phase 7 design contract (binding)

`BRAND_DESIGN_SYSTEM.md` is the authority; this is the operative summary for the phase about to
start.

### Phase 7 **may**

- assemble the Portfolio Command Center and Green-at-Risk from existing primitives;
- add **view models** to `src/presentation/view-models.ts` for data shapes it needs;
- add a *composition* — a screen-level layout arranging existing components on the 12-column grid;
- call `ApplicationGateway.request()` for every application query and command;
- add a **view** to `VIEW_ROUTES` when a screen needs one the table does not carry.

### Phase 7 **must** (semantics settled at the entry gate)

1. **Distinguish the two Green-at-Risk findings.** `MET-FCST-025` System Green-at-Risk answers *"looks
   healthy, predicted to deteriorate"*; `MET-HLTH-033` Reported Green Risk answers *"still reported
   Green, evidence disagrees"*. Show both verdicts and both bands. Never write Reported RAG.
2. **Rank by `rankInterventionPriority()`, and show why.** Every row carries `outranksBecause` — the
   one tier that separated it from the next. AC-1's thirty seconds are spent on *why is this first*,
   not on trusting a number.
3. **Display the capped confidence band, and its reason.** `band` is what may be shown;
   `arithmeticBand` and `bandCappedBy` explain it. A screen that renders `confidenceScore` as a
   headline and calls it confidence has reintroduced DR-018.
4. **Render `insufficientEvidence` projects separately.** They are not safe and must not be sorted to
   the bottom of the ranked list.

### Phase 7 **must not**

1. **Introduce a colour, spacing value, radius or type size not in the token layer.** The build
   fails (G-COLOUR); more importantly, the second screen then needs its own, and there is no system.
2. **Compute a business value in a component.** `PRODUCT_SPEC.md` §8 calls it a defect. Figures
   arrive pre-formatted; `PlottableValue.value` exists only to hit an axis.
3. **Render a status without its glyph and label**, or a chart without a text alternative and a data
   table. Both are enforced by the types.
4. **Style an inference like a fact.** L3 is contained and chipped (§3.3).
5. **Put more than one orange emphasis element in a view** (§8 prohibition 6). If everything is
   urgent, AC-1's thirty seconds have nothing to land on.
6. **Use functional amber or red for anything except status** (§3.2, §10). Not a chart series, not a
   button, not a border.
7. **Implement authorization in React, duplicate the RBAC matrix, or infer permission from a persona
   name** (`SECURITY_MODEL.md` §12.1).
8. **Hand-type the demo marker.** Import the constant; G-DEMO fails the build otherwise.
9. **Read the clock or parse a number in a component** (G-CLOCK, G-FLOAT over `src/presentation`).
10. **Introduce an HTTP transport, server package or `fetch` call.** ADR-0006 is `Proposed` and a
    transport activates DR-029's entire security obligation. `gateway.test.ts` fails the build on
    any of them.
11. **Build a persona or "view as" switcher.** DR-026 is deliberately deferred (register §5a). An
    audience cannot tell a persona selector from impersonation, and one of those is a security claim
    this product cannot make.
12. **Sort or filter client-side and present the result as the whole answer.** Re-arranging an
    already-authorised set is presentation; filtering the page you happened to be given is a wrong
    answer delivered confidently (ADR-0020 D-4).

### The test a Phase 7 screen must pass

> Could this screen have been built without inventing a visual convention?

If not, the gap is in the design system. Fix it in `src/presentation/tokens` and
`BRAND_DESIGN_SYSTEM.md`, with the contrast recomputed — not in the screen.
