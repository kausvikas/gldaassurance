# GlobalLogic Delivery Intelligence — Fixed-Bid Portfolio Command Center

> ## ⚠️ DEMO — SYNTHETIC DATA
> This repository is a proof of concept. It contains **no real client, employee, or financial
> data** and must never be connected to production systems.

---

## The question this product answers

> **"Will this project deliver the contracted scope, by the committed date, within the economics we
> sold — and if not, how early can we detect deterioration, how much value is at risk, why is it
> happening, and what intervention can change the outcome?"**

**The differentiator:** identifying **Green projects moving toward Amber/Red while intervention can
still change the outcome.**

---

## Status

**Phase 7 PASS WITH DEBT — the Portfolio Command Center is built. Phase 8 may begin.**

The executive landing surface answers six questions from one screen: how large the portfolio is,
where margin is forecast, how much GM is at risk, how many projects are already Amber/Red, which
Green projects are deteriorating, and **where to intervene first** — the last named above the table
with the tier that decided it, so the ranking is arguable rather than asserted. It is assembled
entirely from Phase 6 primitives; no new visual convention was invented.

**Open [`docs/design/portfolio-command-center.html`](docs/design/portfolio-command-center.html) at
1440×900.** Three personas, each rendered from a payload that actually passed through the
authorization pipeline: the CDO sees 91 projects and $542.20M, the EMEA director sees 34 and
$172.65M with a **disjoint** project set, and the Delivery Manager is denied without disclosure —
AC-5, visible rather than asserted.

The visual language now exists as tokens, 24 components and an application shell, and it is enforced
by the build rather than by review: a hex value in a component fails the architecture gate, a
hand-typed `DEMO — SYNTHETIC DATA` marker fails it, and a status badge without a glyph and a label
cannot be constructed because the type requires both. Every contrast ratio
[`BRAND_DESIGN_SYSTEM.md`](BRAND_DESIGN_SYSTEM.md) publishes is **recomputed from the palette by
test** — which caught four wrong figures in a draft before they reached a deck.

Security remains structural underneath it: server-side RBAC + ABAC, object-level checks, field
classification with omission (never masking), an append-only audit log with before/after
fingerprints, and telemetry that cannot carry a rate card. **247 of the 746 tests are authorization
tests** (25 of them scripted attacks) and **125 are design-system and accessibility tests**.

**Open [`docs/design/component-gallery.html`](docs/design/component-gallery.html) at 1440×900** —
every primitive in every state, regenerated by `npm run verify` so it cannot drift.

```bash
npm run verify                # typecheck + architecture + schema + lint + 746 tests + data + gallery
npm run test -- tests/a11y    # the 125 design-system and accessibility tests
npm run test -- tests/authz   # the 247 authorization tests on their own
npm run assess:curated        # writes docs/PHASE-4-CURATED-ASSESSMENT.md — the Phase 4 gate
```

**What the controls caught — the first two would have shipped otherwise.** `UnclassifiedField` threw
on two audit fields nobody had classified since Phase 2; a separation-of-duties test caught
`data.applyCorrection` granted to `SECURITY_ADMIN`, which would have let the one role that can widen
anyone's scope also alter financial facts; and the closure pass found the demo-provider startup guard
had never been wired to the configuration vocabulary.

**The gap that matters:** there is **no transport**. ADR-0006 is `Proposed`, so the security headers,
the CSRF requirement and the cookie attributes are declared and tested as *configuration* and nothing
serves them (**DR-029**). Authentication is a labelled persona selector that throws outside a demo
environment (**DR-023**). Read [`PHASE_HANDOFF.md`](PHASE_HANDOFF.md) §0.4 before building any UI.

**[ADR-0016](docs/adr/ADR-0016-phase-5-security-conflicts.md) is Accepted.** Its four conflicts are
settled: product personas and security roles are intentionally **decoupled** (mapping in
`SECURITY_MODEL.md` §4.1a); the classification taxonomy stays **data-centric** and gains
**`SECURITY_TELEMETRY`**; **omission** is the default unauthorised-field behaviour; and security
telemetry gets a narrow, audited investigative grant to `ASSURANCE_AUDITOR` alone rather than a
blanket `PERSONAL_DATA` opening.

**The Phase 7 entry gate is satisfied.** C-10 (Green-at-Risk means two distinct findings) and MC-5
(intervention priority is a lexicographic tiered ordering, not a score) are resolved in
[ADR-0018](docs/adr/ADR-0018-green-at-risk-semantics.md) and
[ADR-0019](docs/adr/ADR-0019-executive-intervention-priority.md); DR-018, DR-021 and DR-041 are
closed; **no HTTP transport was introduced**, so ADR-0006 stays `Proposed` and DR-029 stays closed
([ADR-0020](docs/adr/ADR-0020-phase-7-interaction-architecture.md)).

Every open debt item carries an owning phase, a target gate and its closure evidence in
[`docs/SECURITY_DEBT_REGISTER.md`](docs/SECURITY_DEBT_REGISTER.md). **28 open; none blocks starting

**The honest limit on the UI:** nothing has been verified in a browser — no axe run, no keyboard

## The architecture, enforced

The nineteen bounded contexts and their dependency rules are declared in
[`architecture/manifest.json`](architecture/manifest.json) and enforced on every commit by three
callers sharing one ruleset: the CI gate, the test suite, and an ESLint rule. A violation names its
code, its rule, and the artifact that governs it:

```
ARCH-003: "quality" (tier 2) may not depend on "health" (tier 3).
          A fact does not know its own score.
          authority: ARCHITECTURE_DECISIONS.md §4.1 rule 3, ADR-0004 §2
```

## The five foundational decisions

| ADR | Decision |
| --- | --- |
| [0001](docs/adr/ADR-0001-poc-architecture.md) | Modular monolith, 19 strictly enforced bounded contexts |
| [0002](docs/adr/ADR-0002-decimal-safe-money.md) | Decimal-safe money; the margin bridge reconciles to the cent |
| [0003](docs/adr/ADR-0003-three-baselines-temporal-model.md) | Three baselines; As-Sold immutable; append-only weekly snapshots |
| [0004](docs/adr/ADR-0004-fact-derived-inferred-layering.md) | L1 fact / L2 derived / L3 inferred; the AI never computes an authoritative number |
| [0005](docs/adr/ADR-0005-server-side-authorization.md) | Server-side authorization, scope + field level, with read-auditing |

Phase 1 proposes [ADR-0006 through ADR-0012](docs/adr/README.md) — BFF and versioning, data
strategy, integration, observability, deployment, and two that resolve conflicts found between
existing artifacts. ADR-0013 and ADR-0014 are `Accepted`;
[ADR-0015](docs/adr/ADR-0015-phase-4-engine-conflicts.md) records the four Phase 4 conflicts and is
`Proposed`. **A `Proposed` ADR is not implemented and no code may depend on it.**

## The invariants, in short

1. **The As-Sold baseline never moves.** Variance is meaningless if the reference point drifts.
2. **Pending change requests are never forecast revenue.**
3. **Money is decimal, computed server-side.** The browser renders; it does not decide.
4. **Authorization is server-side.** Hiding a field in the UI is not a control.
5. **Facts, calculations and inferences stay separate** — and are visibly distinguishable.
6. **The AI explains; it never calculates.** No number it types reaches the screen as a fact.
7. **Health and data confidence are two numbers**, never blended into one.
8. **Reported RAG, System-Assessed RAG and Override are three values**, never merged — their
   divergence is the most valuable signal in the product.
9. **Nothing is "complete" if it is mocked, placeholder, or untested.**
10. **Nothing changes silently.** Formulas, boundaries, security, brand tokens and scenarios change
    only through an accepted ADR.
